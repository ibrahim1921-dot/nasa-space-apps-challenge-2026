# Crew Health Monitor (working name)

NASA Space Apps Challenge 2026 entry for **[Create Health Monitoring Software for Astronauts on Space Missions](https://www.spaceappschallenge.org/2026/challenges/health-monitoring-software/)**.

A visual tool that helps astronauts check their own health during a mission, compare each reading with their own normal, and know when to act or call the Crew Medical Officer or flight surgeon. On a Mars mission help can be many minutes away, so the essentials work on board without a link to Earth.

> Prototype for decision support. Not a medical device and not a diagnosis.

## How the parts connect

```
ml/  ──(JSON files in ml/outputs/)──►  backend/  ──(REST, docs/api-contract.md)──►  frontend/
```

- **ml** turns raw datasets into scored, cleaned JSON files in `ml/outputs/`.
- **backend** serves those files and the crew's own readings through the API in [docs/api-contract.md](docs/api-contract.md), and applies the scoring rules.
- **frontend** only talks to the backend API.

The API contract is the agreement between the three groups. Change it in a pull request that all three leads review.

## Getting started

See [docs/setup.md](docs/setup.md) for each part. In short:

| Part | Run locally | Default address |
| --- | --- | --- |
| frontend | `cd frontend && npm install && npm run dev` | http://localhost:3000 |
| backend | `cd backend && ./mvnw spring-boot:run` (Windows: `mvnw.cmd spring-boot:run`) | http://localhost:8080 |
| ml | `cd ml && python -m venv .venv`, activate, `pip install -r requirements.txt` | notebooks in `ml/notebooks/` |

## Data

Every value in the app is labelled with its source: **NASA**, **general human data (PhysioNet)**, **environment**, or **synthetic**. Sources are never merged into one training table. Full list and licences: [docs/data-sources.md](docs/data-sources.md).
