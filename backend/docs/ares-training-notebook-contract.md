## Synthetic cohort and label construction

Cell 8 builds `df_opt` with **3,000** rows. It independently samples each feature
column with replacement from several cleaned source tables. Even systolic/diastolic
pressure and the originally paired sleep/mood columns are sampled independently.
These are constructed feature vectors, not a demonstrated coherent cohort of
astronauts with synchronized multi-indicator measurements.

The code's preselection filters are:

- systolic pressure 95–128, diastolic pressure 60–82, heart rate 55–88 and temperature
  36.3–37.3, using inclusive `between` filters on the source vital-sign rows;
- sleep duration ≥6.2 and constructed mood proxy ≥3;
- grip source value ≥30;
- bone deviation source value ≥−0.9;
- glucose and radiation are sampled without analogous bounds in this code.

These are **dataset-construction filters**, not medical normal ranges or justified
deployment input limits. They are not substituted for the existing service's numeric
transport limits and do not establish the actual saved bundle's training domain.

The copied cohort becomes `master_df`; there is no additional warning cohort,
critical cohort, jitter or augmentation in the supplied code. `assign_risk` defines:

| Numeric training label | Synthetic rule in the notebook |
|---|---|
| 2 | bone deviation value <−2.0 **or** radiation source value >0.40 |
| 1 | otherwise, sleep duration <6.0 **or** grip source value <28.0 |
| 0 | otherwise |

These numeric labels are generated by hardcoded synthetic rules, not independent
clinical ground truth. The notebook does not define the display strings
Optimal/Warning/Critical; those names came from the separate blueprint.
The numeric label rules do not validate those names as clinical risk categories.

**Internal contradiction:** sleep values selected at ≥6.2 cannot satisfy <6.0,
and grip values selected at ≥30 cannot satisfy <28. Therefore class 1 cannot occur
in `master_df` as written. The bone part of the class-2 rule is also excluded by the
≥−0.9 filter. Radiation can still produce class 2 if the source contains values above
0.40. Depending on the source data, the reachable class set is a subset of `{0,2}`;
the code cannot yield class 1. This reasoning does not require running the notebook
or assuming any clinical interpretation of its numbers.
